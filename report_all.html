ข้อค้นพบข้ามรอบ (พร้อมที่มาของหลักฐาน)

  • ความแปรปรวนของชั้น LLM extraction ใหญ่กว่าความต่างระหว่าง STT engine — จาก transcript เดิมเป๊ะ: chirp 7→5 tasks, gemini 6→7 (รอบ 140); task "Broadcasting" ที่ทุก transcript มีครบแต่ไม่มีใครตั้ง (รอบ 60); เฉลย production เองยังสลับภาษาไทย/อังกฤษระหว่างรอบ → ก่อนเลือก engine ควรทำชั้น LLM ให้นิ่ง (temperature / รันหลายรอบแล้ว merge) แล้ววัดซ้ำ
  • ความแม่นชื่อเฉพาะเป็นตัวแยกจริงของ STT — chirp แม่นสุด (AIT, SCG, ลำซัม) แต่ก็ไม่ชนะ task เสมอ; task เดียวกันได้ชื่อผู้ติดต่อ 3 แบบ: เฉลย "Khun Pa" / muse "พี่ป๊ะ" / gemini "พี่เตย" (รอบ 140) — กระทบ assignee resolution ตรง ๆ
  • gemini มี language drift ซ้ำทุกรอบใหญ่ — chunk เสียงเบาถูกถอดเป็นจีน/ฮินดี/ญี่ปุ่น (2 chunks รอบ 60, 6 chunks รอบ 140) ต้องกรอง script แปลกปลอมฝั่ง service ถ้าจะใช้
  • เสถียรภาพ: ทุก engine มีมุมพังของตัวเอง — chirp: 503 ชั่วคราวแล้ว retry production ไม่ครอบ (ปักงานแก้ไว้แล้ว) · muse: ตอบ byte ที่ไม่ใช่ UTF-8 กลาง response 1 ครั้งใน ~950 chunks · gemini: chunk เงียบเคยคืน response ไม่มี content — client ต้องกันทั้งสามแบบ
  • ความเร็วไม่ใช่ประเด็นตัดสิน — ทุกตัว RTF ≤ 0.06 (ประชุม 1 ชม. ถอดเสร็จภายใน ~4–21 นาที) เพียงพอกับงาน batch ทั้งหมด

…ไม่ใช่ว่าเดี๋ยวเหมือนเขามันยังนึกภาพไม่ออก ได้ครับก็นัดมาอีกทีนึงว่าจะยังไงก็ลองส่งราคามาให้เขาประชุมใหญ่ก่อนก็ได้… (ไม่มี "ให้ทางทีมกลับไปเวิร์ค")
